# swu_dormi_admin 기능 개발 오케스트레이터

샬롬하우스 모바일 관리자 앱의 기능 개발을 `flutter-dev`, `firebase-firestore` 두 에이전트로 조율한다.

## Phase 0: 컨텍스트 확인
- `_workspace/`가 있으면 이전 작업 산출물을 먼저 읽고, 사용자 요청이 부분 수정이면 해당 에이전트만 재호출한다.
- 없으면 신규 요청으로 처리한다.

## 실행 모드
**서브 에이전트 패턴.** 이 하네스는 2개 에이전트 협업이지만 대부분의 요청이 "화면 하나 고치기/추가하기" 수준의 단일 스레드 작업이라 실시간 팀 조율 오버헤드가 이득보다 크다. `Agent` 도구로 순차/병렬 호출한다.

## 워크플로우

1. **분석**: 요청이 Firestore 스키마/쿼리 변경을 포함하는지 판단한다.
2. **Firestore 우선 처리**: 컬렉션/쿼리 변경이 필요하면 `firebase-firestore` 에이전트를 먼저 호출해 서비스 레이어를 갱신한다.
3. **UI/로직 구현**: `flutter-dev` 에이전트를 호출해 화면/위젯을 구현한다. 1번에서 나온 서비스 변경 내역을 프롬프트에 전달한다.
4. **검증**: `flutter analyze` 결과를 확인하고 이상이 있으면 `flutter-dev`에 재수정을 요청한다(1회 재시도, 실패 시 남은 이슈를 사용자에게 보고).

## 에러 핸들링
에이전트 실행 실패 시 1회 재시도 후에도 실패하면, 해당 부분 없이 진행하고 결과 보고에 누락을 명시한다.

## 테스트 시나리오
- **정상 흐름**: "시설 신고 목록에 사진 여러 장 첨부 기능 추가해줘" → firebase-firestore가 `facility_reports` 스키마에 photo 배열 필드 지원 확인 → flutter-dev가 UI 구현 → analyze 통과
- **에러 흐름**: 존재하지 않는 컬렉션을 참조하는 요청 → firebase-firestore가 스키마 부재를 보고 → flutter-dev 호출 전에 사용자에게 확인 요청
